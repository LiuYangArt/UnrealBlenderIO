# UE 静态资产自动生成 UCX 碰撞

## 背景

UBIO 已经支持 UE 静态资产往返 Blender，但目前缺少针对大型场景模型和大型道具的自动碰撞生成流程。手工制作 UCX 碰撞耗时，直接使用渲染网格又会保留过多小特征，影响性能和角色移动。

## 目标

实现从 UE 导入资产，在 Blender 中按每个 UE 资产整体生成可编辑的 UCX 凸碰撞体，再导出并回导 UE 的工作流。

重点支持地面、大型平台、大型道具和带规则矩形门洞/窗洞的墙体。过滤螺丝孔、细缝、碎片和不影响行走的小特征。

## 范围

- 多个 UE 资产组合中的每个资产独立处理
- Operator 参数：最大凸体数量、分解误差/凹陷容忍度、最小体积、最小厚度、特征过滤和地面处理
- 采用可随插件分发的成熟凸分解工具
- 生成 `UCX_<资产名>_<编号>` 对象并放入独立碰撞集合
- Blender 中预览、撤销、重复调整和手工修正
- 规则墙体门洞/窗洞保留
- FBX 导出前检查与 UE 回导验证
- 中英文界面本地化

## 非目标

- 任意复杂洞口的全自动识别
- 非闭合扫描网格的完全自动修复
- 螺丝孔和细小装饰特征的精确保留
- 第一版保证所有模型无需人工检查

## 验收标准

- 每个 UE 资产单独生成碰撞结果，资产之间不互相污染。
- UE 能识别生成的 UCX 碰撞体。
- 地面和大型平台上角色移动不会因小特征明显卡脚。
- 规则墙体的矩形门窗保持开口；满足角色尺寸的门洞通过通行测试。
- 参数可在 Adjust Last Operation 中修改，操作支持撤销。
- 失败对象有明确报告。

## 完整实施计划

# UE 静态资产自动碰撞生成计划

## 目标

为 UBIO 增加从 UE 导入静态资产、在 Blender 中自动生成符合 Unreal Engine 规范的 UCX 碰撞体、再随 FBX 导回 UE 的工作流。

目标是保留大型结构和角色移动需要的连续表面，主动丢弃螺丝孔、细小凹槽、碎片和不影响行走的小特征。生成结果允许用户在 Blender 中检查和调整。

## 已确定的产品边界

- UBIO 可以一次导入多个 UE 资产组成的组合。
- 每个 UE 资产作为一个整体单独处理，不把不同资产合并成一个碰撞问题。
- 第一版优先支持地面、大型平台、大型道具和规则墙体。
- 规则墙体的矩形门洞、窗洞属于第一版目标。
- 暂不承诺任意复杂洞口、非闭合扫描网格和细薄装饰结构的全自动正确处理。
- 允许随插件分发成熟的凸分解工具。
- 生成的对象必须遵守 UE 的 UCX 命名和导入约束。

## 用户流程

1. 从 UE 导入一个或多个静态资产组合。
2. 用户选择一个或多个 UE 资产；按源资产身份分组，每个资产整体独立处理，同一资产的多个实例只生成一次并同步。
3. 执行“生成 UE 碰撞”操作。
4. Operator 参数出现在 Blender 的 Adjust Last Operation 面板中，可重复调整和撤销。
5. UBIO 复制并预处理目标网格，删除或过滤小于阈值的特征。
6. 调用凸分解工具生成多个凸碰撞体。
7. 将结果放入独立的 UBIO Collision 集合，按 `UCX_<资产名>_<编号>` 命名。
8. 以绿色线框显示碰撞体，并绑定到对应 UE 资产。
9. 用户检查门洞、窗洞、地面连续性和角色行走区域，必要时手工调整。
10. UBIO 导出 FBX，重新导回 UE，并执行命名、数量和变换检查。

## Operator 参数

第一版参数放在 Operator 中，默认采用项目已有的可重复执行交互模式：

- 最大凸体数量
- 最大分解误差或最大凹陷容忍度
- 最小碰撞体体积
- 最小保留厚度
- 小特征过滤强度
- 是否启用规则墙体洞口保留
- 洞口识别的最小宽度、高度和深度（如实现需要）
- 是否对地面做平滑和小台阶过滤

参数名称、描述、运行时提示必须同时加入 `zh_HANS.json` 和 `en_US.json`，代码中只引用统一本地化接口。

## 处理策略

### 资产边界

以源 UE Static Mesh 资产路径为身份；先核实 UBIO 现有资产元数据并复用。资产内部可以包含多个 Blender 对象，但不同资产不能共同分解。组合、蓝图组件和关卡实例不能替代资产身份；同一源资产只生成一套碰撞，复用现有实例同步机制。

### 网格预处理

- 应用必要的局部变换并保留导出坐标一致性。
- 删除孤立小组件和低于最小体积的连通区域。
- 对过小孔洞和细缝进行填补或忽略。
- 对地面和行走区域删除细小凸起，避免角色脚部卡顿。
- 保持门洞和窗洞所在的大尺度空腔。

### 凸分解

优先评估可随插件分发的成熟工具，首选评估 CoACD，核实维护状态、许可证和 Windows 分发后确定唯一后端，不引入多后端兼容层。UBIO 负责输入预处理网格、传递 Operator 参数、接收凸体结果和生成 Blender 对象；分解算法本身不在第一版自行重写。

### 规则墙体

第一版只保证规则墙体中的矩形门洞、窗洞。必要时先将墙体按洞口分成左、右、上、下区域，再分别生成凸体，避免单个整体凸包把洞口填死。

### UE 导出约束

- 碰撞体名称必须与目标渲染网格保持对应关系。
- 每个凸体必须是闭合、有效、近似凸的网格。
- 导出前检查负缩放、未应用变换、重复名称和非流形几何。
- 导出后检查 UE 是否识别预期数量的 UCX 碰撞体。

## 代码落点

- 扩展现有 `collision.py`，复用 UCX 识别、样式、目标绑定和组件同步能力。
- 新增网格预处理模块。
- 新增凸分解后端适配模块，隔离外部工具调用。
- 新增 Blender Operator、面板参数和结果报告。
- 新增导出前碰撞验证。
- 补齐中英文本地化词条。

## 分阶段实施

### 阶段 1：可行性验证

- 选取地面、大型道具、带矩形门洞的墙体作为样本。
- 确定凸分解工具、许可证、Windows 分发方式和 Blender 调用方式。
- 比较凸体数量、误差、速度和洞口保持情况。
- 输出样本结果和失败案例。

### 阶段 2：最小可用版本

- 实现单个 UE 资产整体处理。
- 实现 Operator 参数、预处理、凸分解和 UCX 对象生成。
- 实现 Blender 内可视化检查和撤销。
- 实现 FBX 导出前验证。

### 阶段 3：规则墙体与行走质量

- 增加矩形门洞、窗洞保留策略。
- 增加地面平滑、小台阶过滤和薄片过滤。
- 以角色行走和门洞通行作为验收标准。

### 阶段 4：回导验证和体验完善

- 在 UE 中验证批量导回结果。
- 增加失败对象报告和可定位的日志。
- 优化默认参数、处理速度和结果预览。

## 验收标准

- 对每个输入 UE 资产独立生成碰撞结果。
- 生成对象符合 UCX 命名规则，能够被 UE 识别。
- 地面和大型平台上角色移动不会因小特征明显卡脚。
- 规则墙体的门洞和窗洞保持开口；尺寸足够的门洞须通过目标角色胶囊通行测试，窗洞不默认要求角色能穿过。
- 凸体数量受 Operator 参数控制；每个凸体的顶点预算在后端验证后确定，不预先承诺未提供的参数。
- 生成结果可在 Blender 中撤销、重复调整和手工修正。
- 中文和英文 Blender 界面下，新增文案都能正确显示。
- 对失败或不适合自动处理的资产给出明确报告，而不是静默生成错误碰撞。

## 风险与待验证项

- 外部分解工具的许可证和插件分发方式。
- 非闭合或自相交网格的预处理成功率。
- 规则墙体洞口识别在不同建模习惯下的稳定性。
- 凸体数量、误差和 UE 运行时性能之间的默认取值。
- Blender 导出 FBX 后的坐标、缩放和碰撞命名一致性。

## 实施与验收补充

- 使用 REGISTER、UNDO 和 draw；invoke 校验后直接 execute，不使用执行前阻塞弹窗。
- 重执行必须替换本次生成结果，不能重复累积 UCX；生成成功前保留旧结果，失败时清理临时产物。
- 小零件体积过滤不能代替孔洞填补；填孔、细节简化和连通块删除需要分别验证。尺寸参数按实际单位定义。
- 在资产局部空间生成，验证单位、枢轴、旋转和缩放；负缩放与非均匀缩放要有测试样本。
- 保持简单碰撞用途明确；验证 UE Collision Complexity 实际使用生成的简单碰撞，避免仍走复杂碰撞而误判通过。
- 回导应更新目标资产碰撞，检查渲染模型、材质、LOD、Nanite 设置和实例变换未意外变化；先验证现有 UBIO 往返流程能否满足。
- 不将凸体外扩作为默认防卡脚方案，它可能收窄门洞和抬高地面；以目标角色胶囊尺寸、台阶高度、坡度设置及实际移动验证为准。
- 验证样本至少包含平地、斜坡/台阶、大型凹形道具、矩形门窗墙、同资产多实例和多资产组合。
- 记录生成耗时、凸体数量、顶点数量、外轮廓偏差、洞口净宽净高以及 UE 行走结果。
- 阶段 1 就完成一个最小 UE → Blender → UCX → UE 闭环，再增加批处理、墙体和地面策略。
- 日志和测试资产结果建议落在 artifacts/collision/；具体命令在实现时补入项目 AGENTS.md。
